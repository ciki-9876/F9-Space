# 一句话摘要

OpenAI Codex 团队的 Vaibhav Srivastav 分享了一段 prompt,丢给 Codex 后,它会自动分析历史会话(及 Memories / Chronicle 等数据源),识别用户重复劳动,自动建议或直接打包成可复用的 Skill / Subagent / Automation。

# 长期有效的核心原理(evergreen)

> 这一段无论你以后用 Codex / Claude Code / 国产工具,都成立。

## 核心范式:AI 自我蒸馏(Self-distillation)

让 AI 反向分析用户的历史交互,**找出重复出现的工作流模式**,自动打包成可复用工具。本质上是把"提示词工程"从用户负担,转移给 AI 自己——AI 比你更清楚你重复在做什么。

## 三个层次的自动化产出

1. **Skill / 技能**:把一段重复的任务变成一个可调用的"动作"(如:每次 PR 审查都要查 X)
2. **Subagent / 子代理**:把一类复杂任务交给专门的代理处理,主线程只下发目标
3. **Automation / 自动化**:把高确定性的重复流程直接变成定时/触发任务,用户不再介入

**判断标准**:AI 应**只对高置信度的重复模式自动打包**,低置信度的列出来让用户决定。

## 设计哲学

这种方法的隐含假设是:**用户最大的浪费不是写代码慢,而是没意识到自己在做重复的事**。AI 比用户更善于在长会话中识别这个模式。

类比:好的运营总监不是更努力执行的运营,而是看出"这件事我们做了 5 次了,该建系统了"的人。AI 在做这件事。

# 当前实现(2026 年下半年快照,会过期)

⚠️ 以下涉及的具体功能名称(Chronicle / Memory / Subagent / /goal)是 Codex 在 2026 年中的预览功能,半年内大概率调整。请核实当前接口。

## 两版 prompt

- **v1**:简洁版,聚焦编程类任务(CI 失败、PR 审查等)
- **v2**(升级版):更全面
  - 数据源扩展:Memories + Chronicle
  - 任务范围扩展:从编码 → 写作、规划、沟通等所有工作类型
  - 输出更智能:直接创建高置信度的 Skill / Subagent / Automation,并说明跳过了哪些(及原因)

## 依赖的 Codex 功能(全部为 preview 状态)

| 功能 | 作用 |
|---|---|
| **Chronicle** | 捕捉屏幕内容,了解用户在 Codex 外的重复工作 |
| **Memory** | 记忆用户偏好和上下文,跨会话延续 |
| **Subagent** | 创建专门代理并行处理任务 |
| **/goal** 命令 | 用户定义目标状态后,Codex 持续运行直至达成 |

## 一个值得关注的隐含成本

文章提到网友讨论的两个争议点:
1. **Token 消耗**:Self-distillation 要扫历史 + 推断模式,token 用量显著
2. **维护成本**:自动生成的 Skill / Subagent 越多,维护负担越大,可能反而成新的重复劳动
