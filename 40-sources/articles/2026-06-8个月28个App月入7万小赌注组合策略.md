# 一句话摘要

全职 iOS 开发者 Max 用 8 个月做了 28 个简单 App，月入 $10K。核心策略："小赌注组合"——不追求一个完美产品，而是快速发布大量简单工具，让市场筛选赢家（4个App贡献60%收入），只回头优化已证明有潜力的。2小时做一个App，发布就跑，别回头。

# 关键观点

- **小赌注组合 > 大而全项目**：28个App中只有4个赚大钱，但你不知道哪4个会赢——只有通过快速发布足够多的尝试，才能让市场告诉你答案。80/20 法则。
- **发布就跑，别回头**：App上线后立刻开始下一个。不盯数据、不优化、不加功能。让数据自己说话——上浮的回来优化，下沉的就让它沉。
- **一个App一个核心功能**：用户搜"树识别"就只想拍照看是什么树。不加社区/收藏/分享/高级搜索——其他都是噪音。
- **复用90%代码**：组件库（设置屏/引导页/付费墙/UI元素）拖拽即用，每个新App只写10%新代码。
- **先验证市场再开发**：用ASO工具检查关键词流行度+竞争对手月收入。至少$100-200/月的竞品才值得做。
- **6步方法论**：找关键词→研究竞品定义核心功能→AI规划→复用代码构建→发布继续下一个→回到赢家放大。
- **经济学**：月成本$200-300，月收入$10K，利润率97%。
- **适合人群**：时间有限（全职+有家庭）、能接受90%失败率、想做"解决具体问题的工具"而非"改变世界的产品"。

# 我有疑问 / 不认同的

> 以下由 AI 基于福九处境预生成的反方种子，待审核：

- **"小赌注组合"与你"独立游戏"的最理想方向有本质冲突**：Max做的是"无聊工具App"（树识别、单位转换、习惯追踪）——不性感但能赚钱。而你的核心能力是审美+创意+游戏天赋，你最想做的是有品味的作品。"小赌注组合"模式要求你放弃"作品感"追求"概率"，这可能与你的内在驱动力冲突。→ **调用规则**：本文适合作为"过渡期赚第一桶金"的策略（先用工具App养活OPC，再用利润fund独立游戏开发），但不适合作为终极OPC方向。
- **Max是全职开发者（Flutter熟手），你不是**：他能2小时做一个App是因为有成熟组件库+熟练技术栈。你需要AI来补技术短板，第一个App可能要2周而非2小时。28个App的"组合策略"对你来说可能是"28个两周"= 一年多——如果加上你的碎片化时间，数量会更少。→ **调用规则**：用本文的"组合思维"但调整预期——可能不是28个App而是5-8个尝试，每个2-4周。核心心智模型（多尝试让市场选赢家）依然有效。

## 通用原则(任何 OPC 快速验证场景都适用)

| 原则 | 落地动作 |
|---|---|
| 小赌注组合 > 单一完美产品 | 不要把所有赌注押在一个项目上，做多个小尝试让市场筛选赢家 |
| 发布就跑 | 发布后不盯数据不优化，立刻做下一个。上浮的回来，下沉的放弃 |
| 一个产品一个核心功能 | 用户需要什么就做什么，其他都是噪音。MVP = 最小核心功能 |
| 先验证市场再开发 | 检查竞品收入，确认有人为此付钱，再动手 |
| 复用 > 从零开始 | 建立自己的组件库/模板库，每个新项目只写10%新内容 |
| 90%失败是正常的 | 28个尝试中4个赢就够了。失败不可怕，不尝试才可怕 |

## 场景限定技巧(仅当触发条件匹配时调用)

| 触发条件 | 可调用的技巧 | 出处 |
|---|---|---|
| 完美主义卡住不敢发布 | "确保没Bug+只有核心功能就发布，让用户告诉你答案" | Max的核心建议 |
| 纠结做哪个方向 | 别纠结，做多个小尝试，让市场告诉你答案。你不知道哪个会赢 | 80/20法则 |
| 一个项目做太久想放弃 | 可能不是放弃，是"发布当前版本+开始下一个"。别优化可能没人用的东西 | 发布就跑 |
| 想做OPC但时间有限 | "小赌注组合"策略就是为时间有限的人设计的。每个2-4周，做5-8个尝试 | 适合人群 |

## 不适用场景(AI 不要用本文技巧回答)

- 做独立游戏（游戏需要深度打磨，不是"2小时发布"的东西）
- 追求"作品感"的创作（本文是功利导向的工具App策略）
- 已经验证了方向想做深（那时候该回到赢家加倍投入，不是继续散弹）
