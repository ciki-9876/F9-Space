# 主题定义

Vibe Coding = 用 AI 作为主要编码执行者，人负责方向/判断/审美的开发模式。本领域覆盖：方法论原则、日常工作流、美术出图、工具链。

# 核心框架（跨 source 综合）

## 人机分工模型（OPC分工）

| 人的角色 | AI的角色 |
|---|---|
| 产品经理（定方向/写spec） | 工程师（写代码） |
| 美术总监（审视觉/找参考） | 动画师（出图/切图） |
| QA（判断好坏/报bug） | 执行者（按参数修改） |

## 效率阶梯

| 层级 | 原则 | 效率差 |
|---|---|---|
| L1 | "做好看点"（形容词描述） | 5+轮迭代 |
| L2 | "左亮右暗"（方向描述） | 2-3轮 |
| L3 | 精确参数（px/rgba/ms） | 一次过 |
| L4 | 渲染顺序+全参数 | 一步到位 |

## 日常执行5步

1. 写规矩手册（CLAUDE.md/spec）
2. 先写测试再让AI实现（TDD思路）
3. 精确指令（说清楚改哪里改成什么）
4. 最简技术栈（AI对简单代码理解最深）
5. 频繁commit（每个小单元一次存档）

## 美术出图原则

- 参考图驱动 > 文字描述（找风格图→AI复现）
- 静态素材AI生图，动态交互写代码
- "vibe art"可批量出100+素材/天，但品质天花板有限
- 追求视觉辨识度时：参考图只能覆盖非核心素材，核心视觉语言需原创

# 启动清单（当我说"要开始开发项目"时，AI必须主动提醒）

- [ ] 跨 session 记忆机制是否已搭建（CLAUDE.md + handover）
- [ ] spec 文档是否已写（技术边界+规则+验收标准）
- [ ] 技术栈是否选好（越简单AI写得越准）
- [ ] 美术资产方案是否确定（参考图驱动 or 代码绘制）
- [ ] 测试策略是否确定（先写测试case再让AI实现）
- [ ] commit习惯是否建立（每个小改动一次存档）
