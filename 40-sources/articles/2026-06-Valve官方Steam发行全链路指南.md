# 一句话摘要

Valve 官方在 GDC 分享的 Steam 独立游戏发行方法论：两个核心问题贯穿始终（"做什么游戏？为谁做？"），三阶段营销（开发前期积累愿望单→临近发布验证市场→发布后持续运营）。核心逻辑："先有受众后有产品"——与平台底层算法对抗的产品永远不会成功。小团队/单人开发者比大手游团队更适合 Steam。

# 关键观点

- **两个核心问题**："我在制作什么游戏？我为谁制作这款游戏？" 让游戏本身指导所有营销决策，保持真实性。
- **Steam 的底层逻辑是"匹配"不是"推广"**：Steam 不卖广告、不接受付费推广。算法的工作是"把你的游戏展示给最可能喜欢它的玩家"。你不需要迎合所有人，只需要精准触达目标受众。
- **"先有受众后有产品"vs"先有愿景后有产品"**：Steam 逻辑与手游立项思路完全冲突。很多手游团队转 Steam 血本无归，反而小团队/单人开发者赚得盆满钵满——因为对抗平台底层逻辑的永远不会成功。
- **游戏本身是最好的营销工具**：游戏的开发方式和围绕它建立社区的方式，决定了营销效果。
- **三阶段框架**：
  - **开发前期**：尽早建商店页（预告片/截图/标签/描述），开始积累愿望单。不要把营销留到发布日。去玩家所在的地方（Discord/Twitch/社交媒体）。
  - **临近发布**：封闭测试、试玩版、Steam 新品节——验证市场反馈的试金石。
  - **发布后**：持续更新、折扣、社区互动维持热度。买断制游戏"发布非终点"，爆款都保持高频更新。
- **商店页是"大本营"**：预告片要短+展示玩法（不要先放公司logo）；截图要展示 UI 让人秒懂游戏是什么；标签必须精准（别追热门标签，会让算法推错人）；描述语气要匹配游戏调性。
- **愿望单 = 告诉 Steam 发布时通知谁**：尽早积累，让 Steam 更好地帮你。

# 我有疑问 / 不认同的

> 以下由 AI 基于福九处境预生成的反方种子，待审核：

- **"先有受众后有产品"与你的创作驱动型游戏理想存在张力**：Valve 说"先确定为谁做"，但你做独立游戏的核心驱动力是表达欲和审美——你想做"自己觉得好玩/美的东西"，不是先调研市场需求再设计产品。→ **调用规则**：创作起点可以是表达驱动（先有想做的东西），但在"怎么让人发现它"这一环节必须回到 Valve 逻辑——用精准标签/预告片/描述把你的游戏匹配给对的人。"为谁做"不是决定做什么，而是决定怎么呈现。
- **这套方法论预设你有"足够长的开发前期"来积累愿望单**：Valve 强调"尽早建商店页"，暗示游戏开发周期至少几个月到一年。如果你走"小赌注组合"策略（快速做小游戏），可能没有足够时间积累愿望单。→ **调用规则**：如果做小工具型游戏（快速验证），愿望单策略优先级低；如果做有深度的独立游戏（你的终极目标），必须在开发中期就建商店页开始积累。

# 应用映射(给未来 AI 看的应用指引)

## 通用原则(任何 Steam 独立游戏发行场景都适用)

| 原则 | 落地动作 |
|---|---|
| 两个核心问题贯穿始终 | 每个营销决策前问："我在做什么游戏？为谁做？" |
| 游戏本身=最好的营销 | 把开发过程本身变成营销内容（devlog/进度展示/社区互动） |
| 尽早建商店页积累愿望单 | 游戏有可展示的玩法时就建页面，不等做完。愿望单=发布日的通知名单 |
| 标签精准 > 标签热门 | 用准确描述游戏的标签，让算法把你匹配给对的人 |
| 预告片=展示玩法 | 短、直接、展示核心玩法。不要先放 logo，不要纯CG |
| 发布非终点 | 持续更新+折扣+社区互动 = 长期运营 |
| 小团队的优势 | 你比大厂更能做精准定位的游戏，这正是 Steam 算法奖励的 |

## 场景限定技巧(仅当触发条件匹配时调用)

| 触发条件 | 可调用的技巧 | 出处 |
|---|---|---|
| 准备把独立游戏上 Steam | 三阶段框架：开发前期（商店页+愿望单）→ 临近发布（封测+新品节）→ 发布后（更新+折扣） | 全文核心 |
| 不知道商店页怎么做 | 预告片展示玩法、截图展示UI、描述匹配游戏语气、标签精准不追热门 | 第一阶段细节 |
| 不确定什么时候开始宣传 | 有可展示的玩法就开始，不要等做完。同时在 Discord/社交媒体建"大本营" | Valve 建议 |
| 犹豫要不要参加 Steam 新品节 | 新品节=免费的大规模曝光+验证市场反馈的试金石，应积极参加 | 第二阶段 |

## 不适用场景(AI 不要用本文技巧回答)

- 做手游/微信小游戏（分发逻辑完全不同，Steam 是搜索+推荐，手游是商店排名+买量）
- 做 SaaS 工具产品（虽然"先有受众"原则通用，但具体策略不可迁移）
- 快速验证型小赌注（没有足够开发周期积累愿望单时，优先级低）
