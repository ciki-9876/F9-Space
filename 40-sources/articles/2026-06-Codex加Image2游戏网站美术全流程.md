# 一句话摘要

汇总多位开发者用 OpenAI Codex + GPT Image 2 做游戏美术资产（106 素材/天）、UI/网页实现（参考图→代码）、建站全流程的实操案例。核心方法论：AI 做执行出图，人做审美判断+提供参考图，"参考图驱动"是当前效率最高的人机分工模式。

# 关键观点

- **"参考图驱动"是弥补 AI 审美短板的关键手段**：AI 凭空设计视觉效果平庸，但人去 Pinterest/参考库找风格图→喂给 AI 复现，效率远高于用文字描述审美。审美决策留给人，AI 只负责落地。
- **Vibe Art = Vibe Coding 在美术环节的延伸**：开发者 VibeCreAI 一天替换 106 个游戏素材（场景/道具/天空背景），称之为"vibe art"。不需要导出文件、拖拽素材、手动管理资产。
- **从图到可玩原型不离开工具链**：Image 2 生成画面→ Codex 切割精灵图+生成动画→ GPT-5.5 搭建浏览器游戏原型，全链路在同一生态内完成。
- **模型遇到自身局限会自动降级**：像素画精准编辑时 Image 1.5 反馈"不擅长"，转而用代码去调整像素——工具链内部有自适应能力。
- **建站全流程实操**（Viktor Oddy）：Pinterest 找灵感→ AI 拆前景/背景图层→ 视频生成工具做循环动画→ 对话式描述页面结构→ 参考图纠偏按钮/字体→ 视差滚动效果用自然语言指令→ 最终交付完整品牌网站。
- **当前限制**：总像素数控制在 ~157 万（够屏幕显示，不够高分辨率印刷）。

# 我认同的

- 全部认同。"参考图驱动"和"vibe art 批量化"作为方法论工具箱有效，调用时注意适用边界（见下方疑问段）。

# 我有疑问 / 不认同的

> 以下由 AI 挑刺，我审核认可：

- **"vibe art"解决的是"从 0 到有"，不一定解决"从有到好"**：文章案例都是最简单的视觉需求（2D 休闲素材替换、品牌展示页），一天 100 个素材但质量是"能用"级别。如果我做独立游戏追求视觉辨识度和审美品质，这套批量模式可能只够 Game Jam 级作品，做不到"有灵魂的美术风格"。→ **调用规则**：适用于"不以美术为核心卖点"的项目、原型验证阶段、或需要大量基础素材的场景；追求视觉辨识度的独立游戏美术不能全靠这套方法。
- **参考图驱动本质是"复现已有风格"，与独立游戏的独特性需求冲突**：独立游戏的竞争力往往在于独特的视觉语言，而参考图驱动产出的是"别人风格的仿品"。真正有辨识度的美术风格（如《Cuphead》手绘动画、《Obra Dinn》1-bit 渲染）恰恰是参考库里找不到的。→ **调用规则**：做网站/工具类产品/策略类游戏可大胆用参考图驱动；做"视觉即品牌"的独立游戏时，这套方法只能覆盖非核心素材，核心视觉语言仍需原创。

# 对我有用的部分

> "工具负责做出来，人负责判断好不好看，目前看下来，这是这套工具链最能发挥效率的协作模式。"

# 应用映射(给未来 AI 看的应用指引)

> ⚠️ 本文工具细节（Codex/Image 2 具体操作）可能随产品迭代过时，但方法论骨架（参考图驱动、批量化、人机分工）长期有效。
> **调用时机**：当福九说要用 AI 做游戏美术、做网站、做视觉设计时，主动调用此段。

## 通用原则(任何 AI 辅助视觉/美术创作场景都适用)

| 原则 | 落地动作 |
|---|---|
| 参考图驱动 > 文字描述 | 先去 Pinterest/参考库找到目标风格的图→喂给 AI 复现，不要试图用形容词描述审美 |
| 人做审美判断，AI 做批量执行 | 人定风格方向+筛选结果+提供参考，AI 负责批量生成+切割+编码落地 |
| 图层拆分思维 | 视觉设计先拆前景/背景/元素层，分别处理再合成——方便做视差、动画、替换 |
| 静态素材 AI 生图，动态交互写代码 | 不需要交互的用生图工具；需要动画/物理/交互的用代码实现（与 Vibecoding 原则一致） |
| 工具局限时降级 | AI 工具能力不足时可降级为代码实现（如像素画精编），不必死磕单一工具 |

## 场景限定技巧(仅当触发条件匹配时调用)

| 触发条件 | 可调用的技巧 | 出处 |
|---|---|---|
| 做独立游戏需要批量美术资产 | "vibe art"模式：AI 生图→直接在游戏中加载，跳过导出/拖拽/手动管理；一天可替换 100+ 素材 | VibeCreAI 案例 |
| 做 2D 游戏需要精灵图+动画 | AI 生成画面→切割精灵图→生成动画代码，全流程不离开工具链 | givros 案例 |
| 做网站/落地页需要视觉设计 | 七步建站法：找灵感→拆图层→生成动画背景→对话描述结构→参考图纠偏→扩展区域→替换素材 | Viktor Oddy 实操 |
| UI 设计需要特定风格（按钮/字体/配色） | 去参考库截图→喂给 AI 让它"参照这个风格重新生成"——本质是用参考图替代文字 prompt | Viktor Oddy + Peter Gostev |
| 需要沉浸式环境/全景图 | 大批量图像（1500张）拼合为可环顾的全景体验，类似街景行走 | Peter Gostev 巴比伦花园 |
| 像素风格游戏美术 | AI 生图工具不擅长像素精编时，让 AI 转用代码调整像素——自动降级策略 | chongdashu 测试 |

## 不适用场景(AI 不要用本文技巧回答)

- 高分辨率印刷需求（当前 ~157 万像素上限）→ 需要其他工具或等模型升级
- 3D 建模/骨骼动画/材质贴图 → 不在本文工具链覆盖范围内
- 需要精确像素级控制的 UI（如设计系统组件）→ 参考图驱动可能精度不够，需手动微调
