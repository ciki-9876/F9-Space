# 本会话的核心改动(按重要性排序)

## 1. CLAUDE.md 回答规则修订(规则 3、4)

**为什么改**:库主人明确知识库目标从"个人记忆"转为"工作外脑"。原规则 `topic > insight > dialogue > source` 是溯源优先,但用户做 AI 产品落地工作时,高质量 source 的应用价值可能高于 draft insight。

**改后**:
- 规则 3:**按问题类型分场景**——自我回顾型问题用原优先级;应用决策型问题(做 X 业务/落地时怎么办)用新优先级 `topic > 高质量 source ≈ insight > dialogue > draft source`
- 规则 4:**按 type 分级状态过滤**——insight/topic 仍要 reviewed;source/dialogue 只要不是 archived 都可引用(reviewed 字段语义只对"我自己的判断"有效)

**新 Agent 实操影响**:用户问"做 X 产品时怎么办"类问题时,**优先调用 source 文件的「应用映射」段**,不要泛泛摘录。

## 2. source 模板新增「应用映射」段

**位置**:`60-meta/templates/source.md`,在「对我有用的部分」和「关联」之间

**结构**:两张表
- 通用原则(任何符合主题的工作场景都适用)
- 按场景的具体落法(可选)

**这是给 AI 看的应用指引,不是用户读后感**。新 Agent 录入 source 时必须填这段(除非该 source 对实操无可复用价值)。

## 3. source 类型的迭代审稿流程(2026-06 增补)

**位置**:`60-meta/workflow-A-AI辅助录入.md` 末尾

**4 步流程**(只对 source 类型适用):

1. AI 按模板写草稿、落盘,留「我认同的」「我有疑问 / 不认同的」段空白
2. 用户给初步判断(哪怕只写"全部 / 无")
3. **AI 基于用户处境(米哈游 / 千星奇域 / AI 产品落地)反向挑刺**——提供 2-3 条"反方种子",指出隐含假设、适用边界、用户处境不适用的部分
4. 用户审核挑刺,挑认可的回填到「我有疑问」段(前面加引用块标注"由 AI 挑刺,我审核认可"),升 status=reviewed

**触发逻辑**:用户初判过简(如"全部"/"无")时,AI 主动启动 step 3;用户已自主写了 3 条以上有内容的质疑则可跳过。

**为什么有这流程**:防止判断段退化为格式义务,丢失"用户跟外部观点摩擦"的反向校准价值。这是 KB 从"信息收集"升级为"判断辅助"的关键一步。

# 已知张力(暂无解,新 Agent 注意)

## 张力 1:source 默认 status=draft 但新规则下不被过滤

按 workflow-A,AI 录入 source 时不能自动升 reviewed(等用户审完才升)。但新规则 4 又说 source/dialogue 只要不是 archived 都可引用。**这意味着 draft source 即使没被用户复审也会被 AI 调用**。这是有意设计(避免 AI 对未复审 source 视而不见),但用户应当知道:他录入但未复审的 source 也会进入 AI 的工作记忆。

## 张力 2:工具推荐的真实性 vs 录入便利性

50-tools 的工具来自二手评测文(如 OpenSquilla),无法保证真实存在。当前缓解方案是 `#待核实` 标签 + 推荐时强制声明。**长期解法**:库主人定期清理 50-tools 里的待核实条目,或者建立"录入工具前先 WebSearch 核实"的规则。

## 张力 3:用户初判与 AI 挑刺的边界

source 迭代审稿流程要求 AI 基于用户处境挑刺。但 AI 如果挑刺过度,会让用户疲于应对;挑刺不足又退化回原问题。**经验值**:每篇 source 挑 2-3 条最相关的边界条件即可,优先挑跟用户当前工作场景(AI 产品落地、运营后台、千星奇域)直接相关的。

# 协作风格(库主人偏好)

(基于本会话观察,新 Agent 可参考)

- **语气直接、不啰嗦**:用户喜欢一针见血的判断,不喜欢"这是个好问题"式开场
- **结构化输出**:用表格 / 编号列表 / 前置摘要,不要长段落
- **不自作主张**:重要决定(删文件、升 status、改全局规则)先问后做
- **诚实承认能力边界**:不要硬编(像本次 OpenSquilla 不联网核实就是个反例,本应早用 WebSearch)
- **方案先行**:做之前先给方案 + 选项,等用户确认再执行
