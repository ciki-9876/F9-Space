# 问题(尚无完整结论)

我想做一个桌面宠物 Agent——有人格、有视觉形象、能自主进化的陪伴型 AI 产品。目前只是想法阶段，不是现在要做。

# 已知的设计约束(来自知识库已有知识)

| 维度 | 约束 | 来源 |
|---|---|---|
| 自迭代闭环 | 需要可量化的评估指标才能全自主迭代；"可不可爱"不可自动量化 | autoresearch 的适用边界 |
| 评估代理指标 | 可能用"用户互动频次""留存时长"作为代理指标，但与"真正好"不完全等价 | autoresearch + 个人判断 |
| 人机分工 | 行为层可自迭代 / 视觉层需人在环 / 人格层用 program.md 编排 | Vibecoding + autoresearch 综合 |
| 视觉独特性 | 桌面宠物的核心卖点是角色设计独特性，"参考图驱动"只能覆盖非核心素材 | Codex+Image2 文章的疑问段 |
| 商业模式 | 属于"卖作品"方向的 OPC 模式 | OPC 护城河 insight |

# 初步架构设想(待验证)

- **人格层**：用 program.md 模式定义宠物性格、行为边界、进化方向——我写"人格文档"，Agent 在框架内自主丰富细节
- **行为层**：对话风格、反应逻辑、动作触发——可设代理指标做自主优化（类 autoresearch 模式）
- **视觉层**：外观、动画、表情——人审美主导，AI 辅助出图（参考图驱动 + 人筛选）
- **技术实现**：待定（桌面端？移动端？Web？）

# 尚未回答的子问题

- 桌面宠物的核心体验是什么？（陪伴感？实用功能？养成乐趣？人格魅力？）
- 竞品分析：现有桌面宠物产品（旅行青蛙、桌面精灵、AI 陪伴类 app）的成功因素是什么？
- "自迭代"对用户来说是 feature 还是 bug？（用户想要宠物"成长"还是"稳定"？）
- 变现模式：付费买断？订阅？内购？
- 技术栈选择：Electron/Tauri？移动端 Widget？浏览器扩展？
- 家庭约束下的开发节奏：每周能投入多少时间？
