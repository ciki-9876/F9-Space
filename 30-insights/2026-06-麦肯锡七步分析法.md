# 框架

遇到复杂问题时，不靠"冒点子"，而是按以下七步系统拆解：

| 步骤 | 做什么 | 关键动作 |
|---|---|---|
| 1. 陈述问题 | 把模糊问题变清晰 | 不断追问"具体到什么程度/什么时间/什么指标"，直到问题可衡量 |
| 2. 分解问题 | 用模型+MECE拆成问题树 | 横向用模型拆（如：收入=流量×转化×客单价×复购），纵向按MECE不重不漏细分 |
| 3. 去非关键问题 | 砍掉低优先级分支 | 看已有数据支持+选高性价比方案（低垂果实优先） |
| 4. 制定工作计划 | 大胆假设 | 列出：问题→假设→求证行动→交付物→负责人→时间 |
| 5. 关键分析 | 小心求证 | 用数据验证假设，不合理就推翻换下一个。大忌：先有结论再找依据 |
| 6. 建构论证 | 提炼模型 | 从数据和素材中沉淀出可复用的方法/框架 |
| 7. 讲清楚 | 交付结果 | 把结论讲给人听，让别人能理解和执行 |

# 核心原则

- **MECE**（Mutually Exclusive, Collectively Exhaustive）：不重不漏。每一层拆分用固定标准，确保覆盖所有可能
- **假设驱动**：不是收集所有信息再决策，而是先假设再用最少的数据验证
- **问题树思维**：把问题可视化为树状结构，避免在散点之间跳跃

# 什么时候用

- 面对复杂业务问题不知道从哪下手时
- 团队讨论变成"各说各的点子"没有收敛时
- 需要系统性地找到增长/降本/优化的杠杆点时
