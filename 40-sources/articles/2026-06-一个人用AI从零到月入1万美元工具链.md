# 一句话摘要

2026 年一个人做 SaaS 产品的完整路径：脚手架10分钟搭基础设施 → 数据库5分钟 → AI辅助开发 → 加AI功能 → 部署收钱。启动成本从1-2.5万美元降到20-50美元，周期从3-6月降到1-2周。350个付费用户 = 月入$10K。竞争维度从"技术能力"变成"选题能力"。

# 关键观点

- **成本坍缩 500 倍**：2020 年做 SaaS 需要 1-2.5 万美元 + 3-6 个月；2026 年只需 $20-50 + 1-2 周。登录/支付/数据库/部署/AI 功能全有免费开源方案。
- **350 人就够了**：月入 $10K 不需要百万用户，只需要 350 个愿意每月花 $29 的人。"一个中等规模的微信群就能装下。"
- **竞争维度转移**：以前创业最大风险是"做不出来"（技术），现在是"做出来没人要"（选题）。但后者更好管理——快速试错，失败成本只有 $20 + 两周。
- **共同模式**：找到痛点 → 做最小产品 → 拿到第一批付费用户 → 迭代。不需要完美，不需要融资，不需要团队。
- **AI 功能 = 护城河**：给现有产品加 AI 层比从零做 AI 产品更有效。有人 $497 API 成本做到 25 倍收入增长。
- **定价建议**：早期先用一次性买断（如终身 $99），制造冲动消费验证市场；订阅制等用户量起来再转。
- **幸存者偏差警告**：死掉的产品比成功的多得多。但核心结论不变——独立做盈利软件产品从未像今天这么容易。

# 我有疑问 / 不认同的

> 以下由 AI 挑刺，我审核认可：

- **本文是 SaaS 路径，不是独立游戏路径**：全文的经济学模型（订阅制/$29月/350人）、获客方式（Product Hunt/Hacker News）、开发节奏（两周出MVP）都绑定 SaaS 产品。我最想做的独立游戏的商业模式/获客/周期完全不同。→ **调用规则**：做 SaaS 工具类 OPC 时调用本文；做独立游戏时不要混用本文的经济学预期。
- **"两周验证"对我的时间约束不现实**：全职工作 + 一岁半小孩 = 碎片化时间。别人的"两周"对我可能是"两个月的周末和晚上"。方法论有效，但预期管理要调整——不要拿"别人两周做出来"来压自己，否则完美主义+时间焦虑双重打击更容易放弃。

## 通用原则(任何 OPC/solo 产品场景都适用)

| 原则 | 落地动作 |
|---|---|
| 选题 > 技术 | 不要纠结用什么技术栈，先验证"有没有人愿意付钱解决这个问题" |
| 350 人心智模型 | 把目标从"做大产品"缩小为"找到 350 个付费用户"——一个微信群的规模 |
| 两周验证一个想法 | 第一版不需要完美，脚手架 + AI 开发，两周上线 MVP 验证市场 |
| 先买断后订阅 | 早期用一次性买断（终身 $99）制造冲动消费、快速验证；有稳定用户后转订阅 |
| 给现有产品加 AI 层 | 比从零做 AI 产品更有效——已有用户+数据+场景，AI 让产品从"能用"变"离不开" |
| 快速试错低成本失败 | 失败了只亏 $20 + 两周，不是灾难。第三个产品才成功是常态 |

## 场景限定技巧(仅当触发条件匹配时调用)

| 触发条件 | 可调用的技巧 | 出处 |
|---|---|---|
| 准备启动第一个 OPC 产品 | Open SaaS 一行命令搭基础设施（登录/支付/邮件/落地页）→ Supabase 数据库 → Vercel 部署 | 01-02+05 段 |
| 纠结技术选型 | 别纠结，用 Open SaaS 或 awesome-opensource-boilerplates 里的 50+ 方案随便选一个，重点是快速启动 | 01 段 |
| 想给产品加 AI 功能 | Flowise（拖拽式，快速验证）或 LangChain（复杂逻辑）；先算 API 成本，$500 以内足够验证 | 04 段 |
| 不确定定价模式 | 先从一次性买断开始（终身 $99），在 Product Hunt / Hacker News 制造冲动消费验证需求 | 05 段 |
| 完美主义发作不敢上线 | "你的第一个产品一定会失败，但失败成本只有 $20 + 两周。第三个才成功是常态" | 07 段 + 幸存者偏差 |

## 不适用场景(AI 不要用本文技巧回答)

- 做独立游戏 → 游戏不是 SaaS，商业模式/分发渠道/开发周期完全不同
- 做面向中国市场的产品 → Stripe 在国内不可用，需要替换为国内支付方案
- 需要大量前期投入的硬件/实体产品 → 本文仅适用于纯软件产品
