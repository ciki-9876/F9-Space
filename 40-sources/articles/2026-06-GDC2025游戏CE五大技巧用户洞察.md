# 一句话摘要

腾讯 i-MUR 用研团队（300次CE/20+款游戏经验）在 GDC 2025 分享的核心方法论：CE 不是为了打分或收集问题清单，而是验证游戏在玩家脑海中留下的"记忆点"是否符合设计意图。五大技巧：收集记忆点（峰终定律）→ 洞察超越语言（看谁在玩/怎么玩）→ 验证"秘方"而非"原料"→ 搭建CE舞台 → 用玩家故事沟通洞察。

# 关键观点

- **CE 的真正目的是验证"记忆点"**：不是让玩家打分评估功能好坏，而是收集"玩完后脑海中留下什么"。《头脑特工队》的"记忆球"比喻——让玩家想再来一次的，是留下的记忆，不是小地图大小。
- **峰终定律在游戏中的应用**：玩家对一段体验的记忆，由高峰时刻+结束时刻决定，持续时间影响不大。CE 挖掘方向=找高光时刻+结束感受。
- **"陷阱问题"vs 正确提问**：❌"打几分？满意/不满意？会下载吗？" ✅"现在什么感受？哪些经历让你有这种感觉？有没有印象深刻的时刻？"
- **洞察超越语言——看"TA是谁"和"TA怎么玩"**：玩家的能力、风格、动机三维度决定了为什么不同人留下不同记忆。玩家会把旧习惯带入新游戏（如狙击手在任何射击游戏里都想狙）。
- **验证"秘方"而非"原料"（汉堡比喻）**：问"掩体够不够"（原料）得不到"地图为什么好玩"的答案。真正该验证的是：游戏想让玩家形成什么感受+什么记忆+通过哪些核心设计实现的。
- **秘方验证三步**：①拆解秘方（总体感觉→关键记忆点→核心设计元素）②收集玩家实际记忆③分析设计意图与实际体验的差距。
- **搭建CE舞台**：①准备有效版本（能体现要验证的秘方即可，美术可临时）②让玩家做好准备（提供基本知识+练习，别让学习成本挡住核心体验）③制定规则（手动匹配平衡、防止不当行为）。
- **用玩家故事沟通**：可视化体验旅程（兴奋曲线）、逐帧回放分析、用玩家大白话（比喻/生动描述/情感词汇）。

# 我有疑问 / 不认同的

> 以下由 AI 基于福九处境预生成的反方种子，待审核：

- **这套方法论的前提是"有团队+有预算做正式CE"，独立开发者资源不足时需要变体**：正式 CE 需要招募玩家、搭建环境、多人观察分析。你做独立游戏时大概率没有这种资源。→ **调用规则**：核心心智模型（验证记忆点、峰终定律、秘方vs原料）在任何规模都适用；但具体执行需要降级为"找5个朋友试玩+问正确的问题+观察他们怎么玩"这种轻量版本。
- **"不问功能好不好"可能对早期独立游戏太极端**：腾讯的游戏已经过了基本可用性阶段，才能聚焦"记忆点"层面。但独立游戏早期可能连基本操作都有问题——这时候功能层面的反馈（"按钮找不到""不知道该干什么"）还是必要的。→ **调用规则**：当游戏已过基本可用性阶段后，才适合用"记忆点"框架做CE；在此之前先解决"能不能用"的问题。

# 对我有用的部分

> "CE不是一个简单的QA环节。就算我们把玩家反馈的问题全都听进去并且改了，游戏就会变得好玩吗？答案显然是否定的。"

> "真正能让玩家日后还想接着玩的，是留在他们脑海中的'记忆点'，可不是因为小地图大小或者能不能和朋友一起玩这些原因。"

> 汉堡比喻："就算我们知道了关于所有食材的答案，我们还是不明白到底是啥让一个汉堡特别好吃……烹饪的方法，也就是你的独门秘方——这才是真正关键的地方。"

> 秘方验证三步：拆解秘方（感觉→记忆→元素）→ 收集玩家实际记忆 → 分析差距

> "CE前先有'秘方'非常重要。一旦有了要验证的秘方，其他事儿就容易多了。这就好比出发前有张清晰的地图。"

# 应用映射(给未来 AI 看的应用指引)

> **调用时机**：当福九做游戏测试/用户研究/评估游戏体验/设计独立游戏的核心循环时，主动调用。

## 通用原则(任何游戏体验验证场景都适用)

| 原则 | 落地动作 |
|---|---|
| 验证"记忆点"而非打分 | 问"玩完后脑海里留下什么"，不问"满不满意/打几分" |
| 峰终定律 | 重点挖掘：体验中最兴奋的时刻 + 结束时的感受 |
| 正确提问 | "现在什么感受？""什么经历让你有这种感觉？""有没有印象深刻的事？" |
| 秘方 > 原料 | 先定义"游戏想创造什么记忆"，再验证这些记忆是否形成，而非逐个检查功能好不好 |
| 看谁在玩+怎么玩 | 理解玩家的能力/风格/动机三维度，才能解释为什么不同人感受不同 |
| 设计意图 vs 实际体验的差距分析 | 预定义期望记忆→收集实际记忆→找差距→分析原因→定迭代方向 |

## 场景限定技巧(仅当触发条件匹配时调用)

| 触发条件 | 可调用的技巧 | 出处 |
|---|---|---|
| 做独立游戏需要测试核心玩法是否好玩 | 秘方验证三步：定义核心记忆→找5人试玩收集记忆→分析差距 | 技巧三 |
| 拿到玩家反馈但不知道怎么用 | 按"记忆分类"整理，对比设计意图，找差距而非逐条修 | 技巧一+三 |
| 不确定测试版本够不够用 | 只要能体现要验证的"秘方"就行，美术/细节可临时 | 技巧四 |
| 想让试玩者体验到核心乐趣 | 提供基本知识+安排练习环节，别让学习成本挡住核心体验 | 技巧四 |
| 要向团队/合作者汇报测试结果 | 可视化体验旅程+用玩家大白话（比喻/场景描述）而非专业术语 | 技巧五 |
| 千星奇域做用户研究/CE | 全套五技巧均适用，正式CE规模 | 全文 |

## 不适用场景(AI 不要用本文技巧回答)

- 游戏还在"基本可用性"阶段（操作都有问题时先修基础，再谈记忆点）
- 非游戏产品的用户测试（核心概念可迁移，但具体手法如"兴奋曲线"更适合游戏）
- 需要定量数据决策时（本文侧重定性洞察，定量 A/B 测试是另一套）
