Component Spec

组件规范

组件规范定义何时使用、基本结构、状态和禁用事项。后续新增组件必须先进入这里。

按钮 Button

访问仓库

用于明确命令。主按钮只用于提交、刷新、分析、保存；次按钮用于访问、取消、清空。

  • 高度不低于 44px，移动端可换行。
  • 主按钮使用 mint → amber 渐变。
  • 危险动作暂不使用红色填充，先用二次确认或低强调按钮。

信息卡片 Card

open-source/radar

卡片顶部显示元信息，中部显示标题和摘要，底部承载访问或分析等操作。

1,280 stars96 forks

用于 AI 情报、GitHub 仓库、笔记列表。卡片只承载一个对象，不嵌套卡片。

  • 最大高度 360px，超出卡片内滚动。
  • 顶部放来源/时间元信息，中部标题与摘要，底部操作。
  • 卡片圆角保持 0px，延续 HUD 面板感。

表单 Form

用于配置、筛选、笔记编辑。表单应清晰标注输入目的，并提供保存后的状态反馈。

  • 敏感信息使用 password 输入。
  • 配置类表单只保存到本地浏览器时必须说明。
  • 提交后必须更新状态文案。

弹窗 Dialog

Repository analysis

这里展示 AI 生成的中文分析。正文区域固定高度，长内容在内部滚动。

用于查看分析结果和短流程确认，不承载复杂编辑。

  • 最大宽度 760px，正文区域可滚动。
  • 标题、关闭、主体、底部动作必须齐全。
  • AI 输出使用 pre-wrap 保留段落。

导航 Navigation

AI Config GitHub Notes Standards

顶部导航只放主要入口；规范页面使用左侧目录承载二级结构。

  • 首页模块入口不超过 5 个。
  • 文档类页面允许 sticky sidebar。
  • 跨页面入口使用真实链接，不用锚点伪装页面。

Patterns

交互模式

反馈

所有异步行为必须有等待、成功、失败三态。失败文案要说明下一步，而不是只显示错误码。

数据录入

配置项就近解释保存位置；API Key 等敏感值不得写入仓库。

数据展示

列表先给摘要，再给操作。长内容在卡片或弹窗内滚动，不撑爆页面。

文案

命令动词统一：刷新、扫描、分析、访问、保存、清空。避免解释 UI 本身。
