# 一句话摘要

Gumroad 创始人把《The Minimalist Entrepreneur》的极简创业哲学封装为 9 个 Agent Skills，形成一条连续路径：社区→验证→MVP→销售→定价→营销→增长→文化→复盘。核心原则：先找社区不先找产品，先手工交付再产品化，从第一天就收费，所有决策回到极简原则校验。

# 关键观点

- **先社区后产品**：创业起点不是"我想做什么"，而是"我理解谁、我能为谁持续提供价值"。先识别你已经属于哪些群体，再从中发现真问题。
- **验证 = 能不能卖出去**：验证标准不是"有没有人说想要"，而是"有没有交易信号"。强行切断"做完再看"的惯性。
- **MVP 三阶段：手工→流程化→产品化**：先靠人交付价值，再把流程写清楚，最后才决定自动化哪一部分。大多数 MVP 不过是 forms and lists。纠正"把 MVP 做成半个完整版"的常见错误。
- **前 100 个客户是"深度获取"不是"规模投放"**：亲友→社区→陌生人三层同心圆。逐个销售、逐个对话、逐个打磨表述。销售是学习过程。
- **从第一天就收费**：定价不只是"给一个价格"，是商业模式校准工具。尽早暴露"有没有经济闭环"的问题。
- **先有 100 客户再谈营销**：营销 = 规模化销售，不是广告投放。邮箱名单比平台粉丝重要。
- **增长以盈利为前提**：hire software not humans，警惕过早招聘和不可逆支出。"活下去"是战略能力不是保守姿态。
- **Minimalist Review 是总校验层**：所有决策从社区/手工优先/最小构建/先卖后扩/盈利性等维度做复盘，防止偏离方法论。

# 我有疑问 / 不认同的

> 以下由 AI 基于福九处境预生成的反方种子，待审核：

- **"先社区后产品"与独立游戏方向存在张力**：这套方法论的底层逻辑是"从社区需求中长出产品"（需求驱动）。但独立游戏的逻辑往往是"创作者先有表达欲/创意，再找到欣赏它的人"（表达驱动）。《Hollow Knight》《Celeste》不是从社区需求调研中诞生的，而是创作者有话要说。→ **调用规则**：做工具/SaaS 类 OPC 时完全适用本文路径；做独立游戏时，"找社区"不是起点而是中点（先做出东西→再找到欣赏它的社区）。
- **"手工→流程化→产品化"在你的碎片化时间约束下有隐含风险**：手工交付意味着你的时间直接绑定收入（做一单赚一单）。对有全职工作+小孩的你来说，"手工交付"的带宽极其有限。如果你的 OPC 起步就选"手工服务"模式，可能会因为时间瓶颈而无法做到足够多的交付来验证需求。→ **调用规则**：对你来说，MVP 可能需要跳过或缩短"手工"阶段，更快进入"产品化"——让产品替你交付价值，你只做判断和迭代。

## 通用原则(任何 OPC/solo 创业场景都适用)

| 原则 | 落地动作 |
|---|---|
| 先社区后产品 | 不要闷头做，先问"我理解谁？我在哪些群体里有信任基础？" |
| 验证 = 交易信号 | 别问"你觉得怎么样"，要问"你愿意现在付钱吗" |
| MVP 三阶段 | 手工交付 → 写清流程 → 才决定自动化哪部分。别一上来就写代码 |
| 从第一天收费 | 免费用户的反馈不如付费用户的反馈真实。哪怕 9.9 元也比免费强 |
| 前 100 客户逐个获取 | 亲友→社区→陌生人。深度对话比广撒网有效 |
| 营销建立在 100 客户之上 | 没有 PMF 之前不要想规模化获客 |
| 增长以盈利为前提 | hire software not humans，警惕不可逆支出 |
| Minimalist Review | 所有重大决策过一遍校验维度：社区相关？最小构建？先卖后扩？盈利可持续？ |

## 场景限定技巧(仅当触发条件匹配时调用)

| 触发条件 | 可调用的技巧 | 出处 |
|---|---|---|
| 纠结 OPC 做什么方向 | 先盘点"我已经属于哪些社区/我理解谁"，从中找真问题 | Skill 1: Find Community |
| 有了想法不确定是否可行 | 别做调研问卷，直接尝试卖——能卖出去就是验证通过 | Skill 2: Validate |
| 准备做 MVP 但不知道做到什么程度 | 先手工交付一次完整价值，再写流程，最后才产品化。MVP = forms and lists | Skill 3: MVP |
| 产品做出来了不知道怎么卖 | 三层同心圆：先找 10 个认识的人→再找社区里 50 人→再扩到陌生人 | Skill 4: First Customers |
| 不知道怎么定价 | 算：生存需要多少收入 ÷ 需要多少客户 = 每客单价。第一天就收费 | Skill 5: Pricing |
| 纠结要不要做某个决策（扩品类/招人/投广告） | 跑 Minimalist Review：社区相关？最小构建？先卖后扩？盈利可持续？ | Skill 9: Review |

## 不适用场景(AI 不要用本文技巧回答)

- 做独立游戏（表达驱动型创作）→ "先社区后产品"不完全适用，创作者先有表达欲再找受众
- 已经有成熟产品想做增长 → 本文侧重 0→1 阶段，增长阶段需要不同框架
- 需要融资/做大规模的项目 → 本文是"极简"哲学，主动压制扩张冲动
